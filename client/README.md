# Drs-Zóna Client

Angular 21 frontend for Drs-Zóna, built with standalone components and Angular Material.

## Requirements

- Node.js `^20.19`, `^22.12` or `>=24`, the versions Angular 21 supports
- pnpm 12 or newer, as set in the `engines` field of [`package.json`](package.json)
- The API running locally with the `https` launch profile (see the [server README](../server/README.md#running-locally))

## Getting started

```bash
cd client
pnpm install
pnpm start
```

The app runs at `http://localhost:4200`. API calls go through the dev proxy to the local API, so start the backend first.

## Scripts

| Command | Description |
| --- | --- |
| `pnpm start` | Starts the dev server; uses `FRONTEND_PORT` from `.env` if it is set ([`scripts/serve.mjs`](scripts/serve.mjs)) |
| `pnpm build` | Production build to `dist/drs-zona/browser` |
| `pnpm watch` | Development build that rebuilds on every change |
| `pnpm test` | Runs the unit tests once with Vitest |
| `pnpm test:watch` | Runs the unit tests in watch mode, rerunning on every change |
| `pnpm open-api-gen` | Regenerates the API client from the running API (see [API client](#api-client)) |

Extra arguments are passed on to the Angular CLI and override the defaults, for example `pnpm start --open`.

## Dev server and proxy

The client calls the API with relative URLs. During development [`proxy.conf.mjs`](proxy.conf.mjs) forwards them to the local API:

| Path | Target |
| --- | --- |
| `/api` | `https://localhost:7221` (`API_HTTPS_PORT`) |
| `/uploads` | `http://localhost:5244` (`API_PORT`) |

The ports are read from the `.env` file in the repository root, or from the file named in `ENV_FILE` ([`scripts/load-env.mjs`](scripts/load-env.mjs)). Without a `.env` the defaults above apply. The API reads the same file, so both sides always agree on the ports.

If you change `FRONTEND_PORT`, add the new origin to `CORS_ORIGINS` as well.

## Project structure

```text
src/
├── app/
│   ├── api/            Generated API client, do not edit
│   ├── services/api/   Services built on the generated client, one per area
│   ├── services/       Error interceptor, form error and image preload helpers
│   ├── interceptors/   Adds the JWT to outgoing requests
│   ├── guards/         Route guards for signed-in users, guests, authors and editors
│   ├── components/     Shared UI: header, dialogs, lists, loading and error states
│   ├── pages/          Routed pages, including the admin pages under pages/admin
│   ├── directives/     Form directives
│   ├── pipes/          Display pipes
│   ├── models/         UI-only models
│   ├── shared/         Shared helpers, such as the Hungarian paginator labels
│   ├── app.config.ts   Application providers
│   └── app.routes.ts   Route table
├── index.html
└── styles.scss         Global styles and the light and dark theme variables
public/                 Static images and the favicon
```

## API client

`src/app/api/` is generated by [ng-openapi-gen](https://github.com/cyclosproject/ng-openapi-gen) from the Swagger document of the running API. Do not edit these files by hand.

After changing the API, start it locally and regenerate the client:

```bash
cd client
pnpm open-api-gen
```

The script reads `http://localhost:5244/swagger/v1/swagger.json` (`API_PORT`). Commit the regenerated files together with the API change.

## Testing

Unit tests run with [Vitest](https://vitest.dev) through the Angular CLI, in Node with jsdom, so no browser is needed.

```bash
cd client
pnpm test               # single run
pnpm test:watch         # watch mode, reruns on every change
pnpm test --coverage    # single run with a coverage report
```

A JUnit report is written to `reports/junit.xml` and coverage to `coverage/`. Both folders are gitignored.

Write specs with the Vitest API (`vi.fn()`, `vi.spyOn()`). `fakeAsync` does not work with Vitest; use `async` tests and `await fixture.whenStable()` instead.

## Build

```bash
cd client
pnpm build
```

The build is written to `dist/drs-zona/browser`. The API serves these files from the same origin, which is why the client uses relative API URLs and needs no environment file.
