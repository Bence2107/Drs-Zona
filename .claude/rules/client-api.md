# API client

## Generated code: `client/src/app/api/`

- Generated by ng-openapi-gen from the running API's Swagger document. Never edit, format or lint these files; ESLint and Prettier ignore the folder on purpose.
- To update it: run the API (`dotnet run --launch-profile https` in `server/API`), then `pnpm open-api-gen` in `client/`. Commit the result together with the server change that caused it.
- If generated code looks wrong, the fix is in the server (route, DTO, return type), followed by regeneration.

## API services: `client/src/app/services/api/`

- One service per API area, `providedIn: 'root'`. A new endpoint gets a method in the existing service for its area; create a new service only for a new API area.
- Services call the generated functions with `this.apiConfig.rootUrl` and map the response body to the generated model type.
- Services are the only place that touches the generated functions and `HttpClient`.

## URLs and environments

- The client uses relative URLs (`provideApiConfiguration('')` in `app.config.ts`). In development `proxy.conf.mjs` forwards `/api` and `/uploads`; in production the API serves the client from the same origin.
- Never hard-code a host, port or `localhost` URL. Do not add `environment.ts` files or Angular file replacements.
